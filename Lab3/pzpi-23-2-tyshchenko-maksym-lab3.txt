3 Web застосунок   
3.1 Мета роботи
Розробка Web-застосунку для системи «Smart Warehouse Asset Tracking»  


3.2 ОПИС ВИКОНАНОЇ РОБОТИ 
Для розробки front-end частини веб-застосунку було обрано сучасний стек технологій: React.js у поєднанні з TypeScript. Це забезпечує надійну типізацію компонентів та високу швидкість реакції інтерфейсу.
Ключові інженерні рішення:
* Рольова модель (RBAC): Інтерфейс розділено на дві робочі області.
   * Менеджер (Звичайний користувач веб-версії): Має доступ до Dashboard (панелі моніторингу залишків), перегляду аудит-логів (Logs) та сповіщень про критичні залишки (Auto-Order).
   * Адміністратор: Має розширений доступ до налаштувань системи, управління профілями працівників складу, а також інструментів роботи з базою даних.
* Інтернаціоналізація та локалізація (i18n/l10n):
   * Використовується бібліотека react-i18next для підтримки української (uk-UA) та англійської (en-US) мов.
   * Форматування дат та часу реалізовано через вбудований API Intl.DateTimeFormat, що динамічно підлаштовується під обраний регіон (наприклад, ДД.ММ.РРРР для України та ММ/ДД/РРРР для США).
   * Сортування текстових значень (назв товарів) у таблицях відбувається з урахуванням правил мови через Intl.Collator.
   * Інтерфейс підтримує зміну напрямку тексту (LTR/RTL) через встановлення атрибута dir у тегу <html>, що робить систему готовою до масштабування на інші ринки.
* Адміністрування та резервне копіювання: * Функціонал управління даними реалізовано через окрему панель.
   * Для бекапів використовується клієнтська генерація файлів (Blob) для експорту налаштувань у форматі .json або бази товарів у .csv.
   * При імпорті застосовується попередня валідація файлу на клієнті (перевірка MIME-типу та структури) перед відправкою на сервер.
2. Взаємодія компонентів веб-застосунку
Web-застосунок (SPA - Single Page Application) працює як незалежний клієнт, що взаємодіє із Backend-сервером через REST API.
* Внутрішня взаємодія: Головний компонент програми (App) ініціалізує сервіс локалізації та перевіряє статус авторизації користувача (через JWT-токен). Залежно від ролі у токені, Router спрямовує користувача або на модулі Менеджера (DashboardMod), або на модулі Адміністратора (AdminMod).
* Зовнішня взаємодія: Зв'язок із сервером здійснюється через HTTP-клієнт (наприклад, Axios). Усі запити проходять через перехоплювачі (interceptors), які автоматично додають токен авторизації та обробляють глобальні помилки (наприклад, 401 Unauthorized або 403 Forbidden при спробі менеджера зайти в адмін-панель).

Показує архітектуру фронтенд-частини та її зв'язок з бекендом.

Демонструє логічну структуру директорій та модулів вихідного коду веб-застосунку.

3.4 Висновок:
Під час виконання третьої лабораторної роботи було успішно спроєктовано та задокументовано архітектуру фронтенд-частини (Web-застосунку) для системи «Smart Warehouse Asset Tracking». Головною метою етапу було створення зручного, безпечного та масштабованого веб-інтерфейсу, адаптованого до потреб різних категорій користувачів.
