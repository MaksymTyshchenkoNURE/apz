Назва та опис системи
Назва системи: Smart Warehouse Asset Tracking
Короткий опис: Клієнт-серверне програмне рішення для цифрової трансформації складських операцій. Система автоматизує збір даних за допомогою емуляції RFID-сканерів (ІоТ), що фіксують переміщення товарів без прямої участі людини. Для працівників передбачено мобільний клієнт для зручного пошуку товарів безпосередньо у проходах складу , а для менеджерів — централізовану веб-панель для моніторингу операцій в реальному часі та контролю запасів.
3. Сфера застосування та обмеження
3.1 Scope of Initial Release У початковому релізі система є робочим прототипом, який реалізує повний цикл взаємодії між серверною частиною, мобільним, Web-клієнтами та ІоТ-обладнанням.
* Серверна частина (Backend): Виступає центральним ядром (єдиним джерелом істини), що обробляє всі запити від клієнтів. Вона виконує перевірку бізнес-правил (зокрема, контролює місткість зон перед переміщенням товарів) та забезпечує збереження стану бази даних за допомогою локального файлу.
* IoT-клієнт: Працює як емулятор апаратного RFID-сканера. Він дозволяє фіксувати зміну зони товару в режимі реального часу за допомогою ідентифікаторів, мінімізуючи ручне введення даних.
* Mobile-клієнт: Розроблений для потреб комірників. Забезпечує функціонал пошуку: працівник може за ключовим словом або частиною назви миттєво перевірити номер зони та доступну кількість конкретного товару.
* Web-клієнт: Панель управління (Dashboard) для менеджерів. Вона дозволяє відслідковувати критичні залишки, генерує попередження про необхідність дозамовлення товарів (Auto-Order Alert) та надає доступ до журналу аудиту (Audit Logs) для моніторингу дій персоналу.
3.2 Scope of Subsequent Releases У наступних ітераціях розробки, окрім переходу на реляційну СУБД та повноцінної клієнт-серверної архітектури, ключовим оновленням стане інтеграція штучного інтелекту (ШІ) для предиктивного управління складом.
* Застосування: ШІ суттєво розширить можливості системи за трьома напрямками. По-перше, алгоритми аналізуватимуть патерни попиту для генерації предиктивних сповіщень про закупівлю ще до того, як рівень товару стане критичним (розширення існуючого алгоритму AUTO_ORDER ). По-друге, ШІ оптимізуватиме маршрути комірників для збору замовлень, зменшуючи час на пошук. По-третє, нейромережі зможуть аналізувати системні логи для виявлення аномалій, що вказують на потенційні крадіжки або збої обладнання.
* Збирання даних: Для навчання та роботи моделей система буде агрегувати великі масиви даних: історію переміщень кожної одиниці товару, частоту та типи помилок (наприклад, спроби помістити товар у переповнену зону ), реальний час пошуку товарів комірниками, а також сезонні коливання залишків. Ці дані структуруватимуться та зберігатимуться у новій базі даних на основі MySQL або PostgreSQL.
* Навчання/використання: Стратегія використання ШІ буде комбінованою. Для завдань предиктивної аналітики запасів доцільно самостійно навчати та донавчати локальні моделі машинного навчання (наприклад, моделі часових рядів), оскільки вони повинні базуватися на унікальних комерційних даних конкретного складу. Водночас, для аналізу текстових логів та виявлення аномалій поведінки раціональніше використовувати готові API сервісів ШІ, щоб заощадити ресурси розробника та уникнути витрат на складне навчання NLP-моделей з нуля.
3.3 Limitations and Exclusions
Зважаючи на поточний та запланований функціонал, система має низку неочевидних обмежень, а також функцій, які були свідомо виключені з розробки:
* Облік виключно за кількістю: Система перевіряє місткість зон лише за кількістю одиниць товару, повністю ігноруючи їхні фізичні габарити чи об'єм. Цей функціонал навмисно виключений для спрощення алгоритмів валідації та структури бази даних у рамках поточного проєкту.
* Відсутність хмарної синхронізації: Хоча сучасні ШІ-рішення часто покладаються на хмарні технології, дана система розробляється для локального використання і не підтримує синхронізацію між різними фізичними складами. Це зроблено для дотримання обмежень нульового бюджету проєкту та спрощення інфраструктури.
* Залежність ШІ від постійного з'єднання: У майбутніх релізах інтеграція сторонніх API для аналізу логів створить неочевидне обмеження — залежність безпеки та аналітики складу від безперебійного підключення до зовнішньої мережі Інтернет.
* Автоматизація фізичного переміщення (Робототехніка): Попри впровадження концепції ІоТ для трекінгу, завдання з фізичного переміщення вантажів залишаються за людьми. Інтеграція алгоритмів управління автономними складськими роботами (AGV) свідомо виключена через несумісність з бюджетом та ресурсами розробки.
