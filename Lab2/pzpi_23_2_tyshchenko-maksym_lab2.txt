2 Мобільний застосунок  
2.1 Мета роботи
Розробка мобільного програмного застосунка для будь-якої поширеної на сьогодні мобільної платформи.  


2.2 ОПИС ВИКОНАНОЇ РОБОТИ 
Для реалізації мобільного клієнта системи було обрано платформу Android та мову програмування Kotlin. Такий вибір зумовлений високою продуктивністю мови, безпекою типів (null-safety) та широкою підтримкою сучасних архітектурних патернів.
Основні архітектурні та технологічні рішення:
1. Архітектурний патерн: Застосунок побудовано за патерном MVVM (Model-View-ViewModel). Це дозволяє чітко відокремити логіку відображення (UI) від бізнес-логіки та роботи з даними, що суттєво спрощує подальше тестування (написання тест-кейсів) та підтримку коду.
2. Мережева взаємодія: Для зв’язку з центральним сервером використовується бібліотека Retrofit. Обмін даними відбувається у форматі JSON через REST API (або його імітацію в рамках прототипу).
3. Асинхронність: Обробка мережевих запитів та складних обчислень реалізована за допомогою Kotlin Coroutines, що гарантує плавність інтерфейсу без блокування головного потоку (Main Thread).
4. Користувацький інтерфейс: Побудований з використанням XML-розмітки (або Jetpack Compose), орієнтований на комірника: великі елементи керування, висока контрастність та мінімум зайвих дій для швидкого пошуку товарів на складі.
2. Будова застосунку та його взаємодія з системою
Мобільний клієнт (Mobile Client) є органічною частиною загальної інфраструктури «Smart Warehouse Asset Tracking».
* Будова: Застосунок складається з двох основних модулів: Модуль авторизації (перевірка ролі працівника) та Модуль інвентаризації (пошук товарів, перегляд зон: Reception, Storage, Shipping).
* Взаємодія: Мобільний застосунок не зберігає головну базу даних локально. При введенні запиту на пошук товару комірником, застосунок формує HTTP-запит (наприклад, GET /api/products?search=...) і надсилає його на Backend-сервер. Сервер перевіряє поточний стан бази (products_db.txt або БД), і повертає JSON із точною зоною та доступною кількістю. Мобільний клієнт парсить ці дані та виводить на екран. У разі втрати зв'язку передбачено локальне кешування останніх результатів пошуку (за допомогою Room Database).
